# crm_team_member

## Source system
This table originates from an Odoo-based CRM system. The naming convention (e.g., `create_uid`, `write_uid`, `write_date`) and the presence of fields like `assignment_domain` are characteristic of Odoo's ORM-generated database schema.

## Functional process 
This table supports the Sales Team management and lead assignment process. It maps individual users to specific CRM teams and defines the parameters for automated lead distribution, such as the maximum number of assignments a member can receive and specific filtering criteria (`assignment_domain`) for incoming leads.

## Description
One row represents a single association between a user and a CRM team, defining their role and lead-handling capacity within that team. This table serves as a raw landing copy of the Odoo `crm.team.member` model, capturing the configuration for how leads are routed to specific team members.

## Caveats for downstream consumers

- **Sensitive Data:** `user_id` links to internal user profiles; ensure access controls are applied when joining with PII-heavy tables.
- **Timestamps:** Timestamps are stored in UTC as per standard Odoo behavior.
- **Soft Deletes:** The `active` column acts as a soft-delete mechanism. Queries should generally filter by `WHERE active = TRUE` unless performing historical analysis.
- **Domain Logic:** The `assignment_domain` column contains serialized domain logic (Odoo's filter syntax). This is not directly queryable in SQL without parsing logic.
