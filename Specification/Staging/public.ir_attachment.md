# ir_attachment

## Source system
This table originates from Odoo (formerly OpenERP), an open-source ERP system. The naming convention `ir_attachment` is a standard Odoo internal table used to manage file attachments across the entire application suite, including CRM, Sales, and Accounting modules.

## Functional process 
This table supports the document management and file storage process within the ERP. It tracks metadata for files uploaded to the system, linking them to specific business records (e.g., invoices, product images, or email attachments) via the `res_model` and `res_id` columns.

## Description
One row represents a single file attachment or binary object stored within the system. It captures the file's metadata, access permissions, and storage location (either in the database or an external URL). This is a raw staging table containing the direct landing of the Odoo attachment registry.

## Caveats for downstream consumers

- **Sensitive Data:** The `db_datas` column contains raw binary data which may include PII or confidential documents; ensure appropriate access controls.
- **Storage Strategy:** Files may be stored in the database (`db_datas`) or on the filesystem (`store_fname`). Queries should check both if attempting to retrieve file content.
- **Timestamps:** `create_date` and `write_date` are typically stored in UTC by Odoo.
- **Soft Deletes:** This table does not implement a standard soft-delete flag; records are generally hard-deleted from the source.
- **Performance:** `db_datas` and `index_content` are large objects; avoid `SELECT *` in production queries to prevent memory issues.
