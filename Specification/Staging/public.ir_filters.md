# ir_filters

## Source system
This table originates from an Odoo ERP environment. The naming convention (e.g., `create_uid`, `write_uid`, `create_date`, `write_date`, `res_id`) and the presence of `domain` and `context` fields are characteristic of Odoo's internal metadata management for user-defined search filters and views.

## Functional process 
This table supports the "User Interface Personalization" process, specifically managing saved search filters and view configurations. It allows users to store custom filter criteria (`domain`) and UI context settings (`context`) for specific system models, enabling personalized navigation and data retrieval experiences within the application.

## Description
One row in this table represents a single saved filter or search configuration defined by a user for a specific system model. This is a raw landed copy of the Odoo `ir.filters` model, serving as the staging point for tracking how users customize their data views and search parameters across the platform.

## Columns

| Column | Type | Nullable | Meaning | Notes |
| :--- | :--- | :--- | :--- | :--- |
| id | INTEGER | false | Surrogate primary key | Sequence-generated by Odoo. |
| user_id | INTEGER | true | Owner of the filter | References `res.users`. Null if global. |
| action_id | INTEGER | true | Associated action ID | Links to the specific UI action. |
| embedded_action_id | INTEGER | true | Embedded action reference | Used for nested view configurations. |
| embedded_parent_res_id | INTEGER | true | Parent resource reference | Used for hierarchical view structures. |
| create_uid | INTEGER | true | Creator user ID | References `res.users`. |
| write_uid | INTEGER | true | Last modifier user ID | References `res.users`. |
| name | VARCHAR | false | Display name of the filter | User-defined label. |
| sort | VARCHAR | false | Sort order definition | JSON or string representation of sort. |
| model_id | VARCHAR | false | Target model identifier | The technical name of the Odoo model. |
| domain | TEXT | false | Filter criteria | Odoo domain expression (list format). |
| context | TEXT | false | UI context settings | JSON/dictionary of view context. |
| is_default | BOOLEAN | true | Default filter flag | Indicates if this is the default view. |
| active | BOOLEAN | true | Soft-delete flag | If false, the filter is hidden/archived. |
| create_date | TIMESTAMP | true | Record creation timestamp | UTC assumed. |
| write_date | TIMESTAMP | true | Last modification timestamp | UTC assumed. |

## Keys

- **Primary key (inferred):** `id`
- **Foreign keys (inferred):** 
    - `user_id` → `res_users.id` (Likely owner of the filter).
    - `create_uid` → `res_users.id` (User who created the record).
    - `write_uid` → `res_users.id` (User who last updated the record).
- **Natural keys (inferred):** 
    - None. The combination of `user_id`, `model_id`, and `name` acts as a functional business key, but is not strictly unique in the schema.

## Caveats for downstream consumers

- **Soft Deletes:** The `active` column is used for soft deletes; ensure queries filter by `active = true` unless auditing archived filters.
- **Timestamps:** `create_date` and `write_date` are stored in the application's system time (typically UTC).
- **Data Complexity:** The `domain` and `context` columns contain serialized Odoo expressions (often Python-like lists or dictionaries stored as text). These require parsing logic if used for downstream filtering.
- **PII/Sensitivity:** While this table contains user IDs and filter names, it generally does not contain sensitive PII, though filter names may occasionally contain user-specific search terms.
