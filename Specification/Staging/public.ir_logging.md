# ir_logging

## Source system
This table originates from an Odoo ERP environment. The naming convention `ir_logging` (Internal Resource logging) and the presence of `create_uid`, `write_uid`, `create_date`, and `write_date` columns are characteristic of the Odoo framework's internal audit and logging infrastructure.

## Functional process 
This table supports the system-wide diagnostic and error-tracking process. It captures application-level logs, including function calls, file paths, and error messages, which are used for debugging, performance monitoring, and security auditing within the ERP instance.

## Description
One row represents a single log entry generated by the application, capturing the context of a specific execution event. It records the location in the code (file path, function, and line number), the severity level, and the associated log message. As a staging table, it serves as a raw, append-only landing zone for system logs before they are processed or archived.

## Columns

| Column | Type | Nullable | Meaning | Notes |
| :--- | :--- | :--- | :--- | :--- |
| id | INTEGER | false | Surrogate primary key | Uses `ir_logging_id_seq` sequence. |
| create_uid | INTEGER | true | ID of the user who created the log entry | References `res_users.id`. |
| write_uid | INTEGER | true | ID of the user who last updated the log entry | Usually null for immutable logs. |
| name | VARCHAR | false | Log name or identifier | Often contains the module or process name. |
| type | VARCHAR | false | Type of log entry | e.g., 'server', 'client', 'error'. |
| dbname | VARCHAR | true | Name of the database instance | Relevant in multi-tenant Odoo setups. |
| level | VARCHAR | true | Log severity level | e.g., 'INFO', 'WARNING', 'ERROR', 'DEBUG'. |
| path | VARCHAR | false | File path of the source code | The file where the log was triggered. |
| func | VARCHAR | false | Function name | The specific method or function name. |
| line | VARCHAR | false | Line number | The line number in the source file. |
| message | TEXT | false | The log message content | The primary descriptive text of the event. |
| create_date | TIMESTAMP | true | Timestamp of log creation | Assumed UTC. |
| write_date | TIMESTAMP | true | Timestamp of last update | Usually matches `create_date`. |

## Keys

- **Primary key (inferred):** `id`
- **Foreign keys (inferred):** 
    - `create_uid` → `res_users.id` (Likely references the user associated with the log event).
    - `write_uid` → `res_users.id` (Likely references the user who last modified the record).
- **Natural keys (inferred):** Not confidently inferable; log entries are typically identified by their surrogate ID and timestamp.

## Caveats for downstream consumers

- **Sensitive Data:** The `message` column may contain PII or sensitive system configuration details; ensure appropriate masking if exposing to non-admin users.
- **Timezone:** Timestamps are assumed to be in UTC, consistent with standard Odoo database configurations.
- **Data Volume:** As a logging table, this can grow rapidly; queries should be filtered by `create_date` to avoid performance degradation.
- **Immutability:** While `write_uid` and `write_date` exist, log entries are generally considered immutable once written.
