# ir_model_data

## Source system
This table originates from Odoo (formerly OpenERP), an open-source ERP system. The naming convention `ir_model_data` is a core Odoo table used to map external XML IDs to internal database records, facilitating data synchronization and module upgrades.

## Functional process 
This table supports the "External Identifier" mapping process. It acts as a registry that links human-readable identifiers (defined in modules) to the internal surrogate keys of records across the system, ensuring that data imports and module updates maintain referential integrity without relying on volatile internal IDs.

## Description
One row in this table represents a single mapping between an external identifier (defined by a module and a name) and a specific record in the system. It serves as a raw landing copy of the Odoo `ir.model.data` model, providing the metadata necessary to resolve cross-references between different system entities.

## Columns

| Column | Type | Nullable | Meaning | Notes |
| :--- | :--- | :--- | :--- | :--- |
| id | INTEGER | false | Surrogate primary key | Sequence-generated by Odoo. |
| create_uid | INTEGER | true | User ID who created the record | References `res_users.id`. |
| create_date | TIMESTAMP | true | Creation timestamp | Defaults to UTC. |
| write_date | TIMESTAMP | true | Last modification timestamp | Defaults to UTC. |
| write_uid | INTEGER | true | User ID who last modified the record | References `res_users.id`. |
| res_id | INTEGER | true | Internal ID of the target record | The surrogate key of the record being mapped. |
| noupdate | BOOLEAN | true | Update protection flag | If true, prevents the record from being updated during module upgrades. |
| name | VARCHAR | false | External identifier name | The unique name defined in the XML/data file. |
| module | VARCHAR | false | Module name | The module that owns this external identifier. |
| model | VARCHAR | false | Target model name | The Odoo model (table) the record belongs to. |

    - `write_uid` → `res_users.id` (Inferred from Odoo standard naming conventions).
- **Natural keys (inferred):** 
    - `(module, name)`: This combination uniquely identifies an external record within the Odoo framework.

## Caveats for downstream consumers

- **Timestamps:** All timestamps (`create_date`, `write_date`) are stored in UTC.
- **Soft Deletes:** This table does not implement soft deletes; records are typically removed physically if the underlying module or data is uninstalled.
- **Sensitivity:** Contains no PII, but `create_uid` and `write_uid` link to user metadata which may be considered sensitive in some compliance contexts.
- **Data Integrity:** The `res_id` column is polymorphic; it points to different tables depending on the value in the `model` column. Ensure your queries join based on the `model` value to avoid cross-table ID collisions.
