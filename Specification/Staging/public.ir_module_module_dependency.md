# ir_module_module_dependency

## Source system
This table originates from an Odoo ERP system, as evidenced by the `ir_module_module_dependency` naming convention, which is a standard internal table structure used by the Odoo framework to manage module dependencies.

## Functional process 
This table supports the module management and dependency resolution process within the ERP. It tracks which software modules are required by other modules to ensure that the system environment is correctly configured before installation or execution.

## Description
Each row represents a single dependency relationship between two modules, identifying a specific module that must be present for the parent module to function. This is a raw landed copy of the Odoo system table, serving as the staging layer for dependency graph analysis and system configuration audits.

## Caveats for downstream consumers

- The `name` column contains the technical string identifier of the required module, not the display name.
- The `module_id` column is nullable in the schema, but should be treated as a mandatory relationship for valid dependency records.
- This table does not contain soft-delete flags; it reflects the current state of the module registry as captured during the last ingestion.
- The `auto_install_required` column defaults to `true`, which may mask missing values in the source system.
