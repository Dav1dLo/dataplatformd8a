# ir_rule

## Source system
This table originates from Odoo (formerly OpenERP), an open-source ERP system. The naming convention `ir_rule` (Internal Record Rule) and the presence of columns like `model_id`, `create_uid`, and `domain_force` are characteristic of Odoo's security and access control framework.

## Functional process 
This table supports the platform's security and access control management. It defines record-level security rules that restrict which users can read, write, create, or delete records based on specific domain filters applied to Odoo models.

## Description
One row represents a single security rule definition applied to a specific Odoo model. This is a raw landed copy of the system's security configuration, used to enforce data visibility and modification constraints across the application.

## Columns

| Column | Type | Nullable | Meaning | Notes |
| :--- | :--- | :--- | :--- | :--- |
| id | INTEGER | false | Surrogate primary key | Sequence-generated by `ir_rule_id_seq`. |
| model_id | INTEGER | false | Foreign key to the target model | References `ir_model.id`. |
| create_uid | INTEGER | true | Creator user ID | References `res_users.id`. |
| write_uid | INTEGER | true | Last modifier user ID | References `res_users.id`. |
| name | VARCHAR | true | Rule name | Descriptive label for the security rule. |
| domain_force | TEXT | true | Filter domain | A Python-like expression defining the data scope. |
| active | BOOLEAN | true | Active status | Soft-delete flag; if false, the rule is ignored. |
| perm_read | BOOLEAN | true | Read permission | Allows read access if true. |
| perm_write | BOOLEAN | true | Write permission | Allows update access if true. |
| perm_create | BOOLEAN | true | Create permission | Allows insert access if true. |
| perm_unlink | BOOLEAN | true | Delete permission | Allows delete access if true. |
| global | BOOLEAN | true | Global scope flag | If true, the rule applies to all users. |
| create_date | TIMESTAMP | true | Creation timestamp | Recorded by the application layer. |
| write_date | TIMESTAMP | true | Last modification timestamp | Recorded by the application layer. |

## Keys

- **Primary key (inferred):** `id`
- **Foreign keys (inferred):**
    - `model_id` → `ir_model.id`: This column links the security rule to the specific database table/model it governs.
    - `create_uid` → `res_users.id`: Tracks which user created the rule definition.
    - `write_uid` → `res_users.id`: Tracks which user last modified the rule definition.
- **Natural keys (inferred):** Not confidently inferable.

## Caveats for downstream consumers

- **Timestamps:** Timestamps are stored in the application's server time (typically UTC), but verify against the Odoo instance configuration.
- **Soft Deletes:** The `active` column acts as a soft-delete flag; ensure queries filter by `active = TRUE` unless auditing historical rule configurations.
- **Domain Complexity:** The `domain_force` column contains serialized Python expressions; these are not directly executable in SQL and require a parser if logic needs to be extracted.
- **Security:** This table contains the logic for system-wide access control; treat it as sensitive configuration data.
