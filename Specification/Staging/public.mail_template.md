# mail_template

## Source system
This table originates from Odoo (formerly OpenERP), an open-source ERP system. The naming convention (e.g., `create_uid`, `write_uid`, `model_id`, `ref_ir_act_window`) and the use of `JSONB` for multi-lingual fields are characteristic of Odoo's ORM layer and its underlying PostgreSQL schema.

## Functional process 
This table supports the automated communication and notification engine within the ERP. It stores templates for outgoing emails, defining the structure, recipients, and content logic used by the system to trigger transactional emails, such as order confirmations, invoice notifications, or system alerts.

## Description
One row in this table represents a single email template configuration, including its subject line, HTML body, and recipient routing rules. This is a raw landed copy from the Odoo staging layer, intended to provide the base metadata for email automation workflows. It captures the template's definition at the grain of a unique template identifier.

## Caveats for downstream consumers

- **Sensitive Data:** The `email_from`, `email_to`, and `body_html` columns may contain PII or internal business communication details; ensure appropriate masking for non-production environments.
- **JSONB Handling:** Fields like `subject` and `body_html` are stored as `JSONB`. Use PostgreSQL `->>` operator to extract text values (e.g., `subject->>'en_US'`).
- **Soft Deletes:** The `active` column acts as a soft-delete flag. Queries should generally filter by `WHERE active = TRUE` unless auditing archived templates.
- **Timestamps:** Timestamps are assumed to be in UTC, consistent with Odoo's internal storage standards.
- **Dynamic Content:** The `body_html` and `subject` fields often contain Jinja2 template syntax (e.g., `${object.name}`) which will not be rendered in the data warehouse.
