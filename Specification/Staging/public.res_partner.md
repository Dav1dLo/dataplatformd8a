# res_partner

## Source system
This table originates from Odoo (formerly OpenERP), an open-source ERP system. The naming convention `res_partner` is the standard technical name for the "Partners" model in Odoo, which serves as the unified registry for customers, suppliers, and internal contacts.

## Functional process 
This table supports the "Party Management" and "Master Data" processes. It acts as the central repository for all entities the organization interacts with, including business partners, vendors, and individual employees. It is used across the lead-to-cash, procure-to-pay, and CRM modules to maintain address books, contact details, and financial settings (e.g., credit limits, payment terms).

## Description
One row in this table represents a single "Partner" entity, which can be an individual person, a company, or a specific contact location (e.g., a delivery address). This table is a raw landed copy of the Odoo `res_partner` model, serving as the primary source of truth for contact master data within the staging layer.

## Caveats for downstream consumers

- **Sensitive Data:** Contains PII including `email`, `phone`, `mobile`, `street`, and `vat`. Masking is recommended for non-authorized environments.
- **Soft Deletes:** The `active` boolean column indicates whether a record is logically deleted. Queries should generally filter by `WHERE active = TRUE`.
- **Timestamps:** Timestamps are typically stored in UTC in Odoo; however, verify against the application server configuration.
- **JSONB Columns:** Many financial and configuration properties are stored as `JSONB`. These require specific PostgreSQL operators (e.g., `->>`) to extract values for reporting.
- **Hierarchy:** The `parent_id` and `commercial_partner_id` columns indicate that this table is self-referential; recursive CTEs may be required to traverse the full organizational structure.
